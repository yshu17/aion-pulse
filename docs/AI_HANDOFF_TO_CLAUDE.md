## 2. Что изменено

- `tools/build_master_plan.py`: единый каталог из четырёх источников и генерация **одного** `docs/plan-model.json`. При следующем добавлении ID сборщик автоматически поставит текущее время Europe/Warsaw и перенесёт отметку «НОВОЕ» на последний новый ID. Последующие правки названия, описания, статуса, исполнителя или связей получают `changed_at` и запись в истории; исходному содержанию при первом учёте дата изменения не приписывается. На Windows без IANA `tzdata` используется локальный часовой пояс системы. `latest` и историческая дата `ui:42` сохранены.
- `tools/plan_shared.py`: общий раскрывающийся обзор внедряется в каждую из пяти страниц. Поиск, фильтры плана/статуса/приоритета, порядок номеров сверху вниз, раскрытие и вложение дочерних задач при наличии `parent`, переход к ID, история, ссылки зависимостей, полоса статусов, краткая схема данных и список последних изменений. Личные изменения статуса хранятся под `aion-shared-plan-ledger-v1` в браузере; экспорт/импорт JSON даёт перенос и резервную копию. - `tools/build_plans_site.py`: ограничена замена вызовов `localStorage.setItem`, чтобы мобильный сборщик не ломал `try` в общем обзоре. Полученный мобильный JavaScript проверен отдельно.
- Добавлен `tests/test_plan_model.py` для уникальных ID, начального каталога, новых дат и одинаковой встроенной модели на пяти страницах.

## 3. Как работать с общей моделью

```text
HTML карты + HTML расписания + Markdown UI/UX + Markdown Telegram
                      ↓ tools/build_master_plan.py
docs/plan-model.json (производный каталог, не редактировать вручную)
                      ↓ встроенная одинаковая модель
MASTER + Telegram + Schedule + UI/UX + Map
                      ↔ личные отметки браузера (экспорт/импорт)
```

1. Меняй исходную задачу в соответствующем плане, сохраняя её ID. Для новых задач используй следующий номер. Не редактируй `docs/plan-model.json` как источник.
2. Запусти последовательно `python tools/build_ui_ux_plan.py`, `python tools/build_telegram_plan.py`, `python tools/build_master_plan.py`, `python tools/build_plans_site.py`. Первые три обновляют пять страниц и общую модель, четвёртый — автономный набор для телефона.
3. `docs/plan-task-meta.json` хранит `latest`, `known_keys`, `source_hashes` и необязательные поля задачи `added_at`, `changed_at`, `parent`, `depends_on`, `history`. Не придумывай исторические даты. Сборщик автоматически запишет дату для впервые обнаруженного ID и дату изменения только при последующей правке источника. Если в рамках одного запуска добавлено несколько задач, отметка «НОВОЕ» выбирается по ключу плана и ID; фактический порядок ручного добавления исходные файлы не хранят.
4. Личные статусы в браузере не синхронизируются через Git, Claude Artifact или Telegram автоматически. Переноси их экспортом/импортом. Исходные статусы для команды меняются в планах и попадают в модель при сборке. Это важно, чтобы случайный щелчок в браузере не означал завершение разработки.

- Основная сборка теперь **`AionChatWatcher.exe` в корне проекта**, 100 110 538 байт, SHA-256 `50BB7E0BA9699B86113EACD2EAD3A727BB3E098A3E895BBF1893D6CBA6BED98D`. - `python -m pytest -q --tb=line` с `TMP`, `TEMP`, `TMPDIR` на `tmp/` и `PYTHONPATH=downloads/notifications_build/vendor`: **286 passed, 6 failed**. ## 6. Нерешённое и что передать Claude Code

1. Сверить шесть тестовых ошибок с незакоммиченным кодом карты/сигнала/темы, затем исправлять отдельными маленькими шагами. До этого полный тестовый набор не зелёный.
2. Проверить общий обзор в браузере и на телефоне. Автоматический Computer Use прекратился до открытия страницы из-за невозможности надёжно определить текущий URL; синтаксис и структура страниц проверены локально. Особенно проверить `localStorage` в мобильном iframe; при запрете хранения обзор покажет предупреждение и предложит экспорт.
3. Решить, удалять ли старую отдельную сборку SN23 и старые папки сборки. Уникальные исторические планы сохранять, если нет отдельного решения владельца.
4. Сохранить разделение: источник реализации — планы в репозитории; личная отметка в браузере — только рабочая пометка. Для настоящего обмена статусами между устройствами понадобится отдельное согласованное хранилище и миграция. Не заменять текущую архитектуру без решения пользователя.
5. Продолжить SN-4 (реальные источники уведомлений); SN-2/3 и новая основная сборка уже готовы. Telegram интеграцию не начинать до явного «делаем» пользователя.
