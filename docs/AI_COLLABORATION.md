# Совместная работа Claude Code и Codex

Claude Code — Lead Developer и владелец архитектурных контрактов, релизов и интеграции. `PAIR.md` — общий журнал и таблица занятых задач. Перед началом работы читать `PAIR.md`, `git status --short` и соответствующий план; после шага обновлять его статус, пересобирать планы и оставлять строку в журнале.

## Разделение по умолчанию

| Область | Ответственный |
|---|---|
| `watcher/`, `main.py`, `data/`, спецификация сборки и exe | Claude Code |
| Извлечение клиентских данных, исследовательские скрипты в `tools/`, отчёты `client_extract/` | Codex по отдельному заданию |
| Генераторы планов, проверка целостности и тесты к ним | Codex; контракт источников согласует Claude |
| `PAIR.md`, планы и документы передачи | Общие файлы: один автор одновременно, после явного назначения задачи |

Малые подтверждённые исправления в зоне другого разработчика возможны по прямому поручению пользователя: сохранить прежние изменения, описать строки и результат теста в `PAIR.md`, передать владельцу для ревью. Большие архитектурные изменения сначала оформить вопросом в `PROJECT_ISSUES.md`.

## Git и передача

1. Для одновременной разработки использовать разные Git worktree и отдельные ветки: `claude/<задача>` и `codex/<задача>` (если ветка Codex создаётся автоматически, соблюдать префикс `codex/`). Общие `config.json`, `build/`, `tmp/`, игровые файлы и личные браузерные статусы не переносить через Git.
2. Перед правкой сверять `git status --short` и текущий `PAIR.md`; чужой незавершённый файл не перезаписывать и не форматировать целиком. В грязной общей копии ограничивать патчи конкретными строками.
3. Один разработчик отвечает за контракт источников и ID планов — Claude. Новые ID не переиспользовать; `docs/plan-task-meta.json` менять через генератор. Сгенерированные страницы пересобирать после источника.
4. Перед передачей: `python tools/check_project.py`, затем маленький коммит только своих файлов и запись в `PAIR.md` с путями, результатом, открытыми вопросами. Если дерево содержит чужие правки, не включать их в коммит и передать diff/описание без смешивания авторства.
5. Claude просматривает diff и прогоняет проверки в своей ветке до объединения. При конфликте вручную сверить источник задачи, локальные статусы и данные; автоматическое слияние конфликтующих правок запрещено.
6. Игровую папку только читать. Скачанное хранить только в проекте по правилам `PAIR.md`. Claude Artifact публикует только Claude.

## Исполнители и инструменты в планах

С 12.10 у каждой открытой задачи всех планов и у этапов черновиков есть блок «AI Tools & Skills» из `docs/plan-ai-tools.json`
(рекомендации пишет Claude; доступность скиллов сборка проверяет по файлам). Поля:

| Поле | Значение |
|---|---|
| `agent` | `claude` — архитектура, контракты, сложная логика, интеграция; `codex` — отдельные компоненты, UI, motion, тесты, отладка, данные клиента; `joint` — обе стороны с разделением файлов; `user` — нужна проверка в игре или решение |
| `reviewer` | кто принимает результат; финальное решение по архитектуре — всегда Claude |
| `split` | кто проектирует, реализует, тестирует, утверждает |
| `files` | владение файлами по исполнителям — в совместной задаче один файл правит один агент |
| `contract` | общий API / ключи `config.json`, которые Claude фиксирует до начала работы Codex |
| `handoff` | `ready` — можно отдавать Codex; `needs-architecture`, `gated`, `blocked`, `user`, `in-progress`, `n/a` |
| `arch_review` | `pending` — ждёт архитектурной проверки Claude |

Задачи, которые трогают один файл (например, `watcher/mapview.py` в map:29, 30, 39 или `watcher/app.py` в ui:36–41),
выполняются по одной; это записано в `note`. Передача задачи Codex — [AI_HANDOFF_TO_CODEX.md](AI_HANDOFF_TO_CODEX.md),
сводка по скиллам — [AI_SKILLS_TASK_MAPPING.md](AI_SKILLS_TASK_MAPPING.md) (генерируется).
