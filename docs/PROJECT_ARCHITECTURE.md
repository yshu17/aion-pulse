# Архитектура Aion Chat Watcher

Состояние на 12.10.2026. Этот файл описывает текущий код; архитектурные решения принимает Claude Code.

## Работа программы

`main.py` создаёт Tk и `watcher.app.App`. `App` загружает `config.json`, каталог предметов, POI и карты из `data/`, создаёт вкладки и запускает таймеры Tk. Отдельного серверного процесса нет. Основной цикл слежения `App._tick` раз в `poll_interval_ms` читает дописанные байты `Chat.log` через `LogTailer`, разбирает чат (`parser`), ищет совпадения (`matcher`), обновляет ленту (`feed`), серии (`series`), сигналы (`alarm`, `notifier`) и центр уведомлений (`notify_center`, `toasts`). «Весь чат» (`allchat`) имеет свой tailer и таймер только при активной вкладке.

Карта: `mapview` загружает описания зон `data/maps/maps.json` и подписи `labels.tsv`; `poi` загружает `poi.json`. Графика зон и значков лежит в `data/maps/`. `mapcard` показывает карточку и соседние точки. Для Бездны указаны три слоя; высотные границы выбора слоя в клиенте не найдены.

Настройки: `watcher.config.Config` сериализуется в `config.json` рядом с exe (или в корне проекта при запуске из исходников). Пользовательские фильтры, ширина списка, сторона и тема карты хранятся там. История уведомлений в `NotificationCenter` ограничена и живёт только в памяти текущего запуска.

## Планы

Источники задач: массив `STEPS3` в `docs/map-poi-plan.html`, массив `STEPS` в `docs/schedule-notify-plan.html`, `UI_UX_IMPROVEMENT_PLAN.md`, `docs/telegram-bridge-plan.md`. `tools/build_master_plan.py` собирает из них `docs/plan-model.json` и пять страниц: MASTER `docs/index.html` плюс четыре тематических. `docs/plan-task-meta.json` хранит постоянные ID, дату добавления и историю изменений исходников. `tools/plan_shared.py` встраивает одинаковую модель и личный журнал статусов в каждую страницу; личные пометки живут в `localStorage`, переносятся экспортом/импортом JSON и не изменяют исходные статусы.

`tools/build_plans_site.py` создаёт мобильную копию в `build/plans_site/`; публикацию Claude Artifact выполняет только Claude. `tools/check_plans.py` сверяет источники, MASTER, ID, зависимости, даты, встроенную модель и локальные ссылки. `tools/check_project.py` запускает его вместе со всеми тестами.

Шесть новых предварительных функций хранятся отдельно в одном источнике `docs/feature-drafts.json` с полем `reviewStatus: DRAFT`. `tools/build_feature_drafts.py`, вызываемый `build_master_plan.py`, создаёт обзор и шесть страниц, а MASTER лишь ссылается на них. Эти черновики не добавлены к 100 утверждённым/действующим задачам пяти основных планов и не меняют их `status` или `plan-task-meta.json`. Мобильный сборщик копирует страницы черновиков; публикация остаётся за Claude.

## Границы данных и сборка

`data/` входит в сборку exe; `client_extract/` — распакованные данные клиента и отчёты; `downloads/` — локальные копии внешних ресурсов и инструментов; `tmp/` — временные файлы. Папка игры только для чтения. `tools/build_*` создают каталоги, карты, значки и HTML. Команда сборки exe описана в `README.md`; полная проверка проекта: `python tools/check_project.py`.

## Известные контракты

- Не менять номера существующих задач; новые ID добавлять после последнего номера источника.
- Сборочные HTML и JSON производны от источников; редактировать их вручную нельзя, кроме самих HTML источников карты и расписания.
- `watcher/` и `data/` — основная зона Claude Code. Codex вносит маленькие подтверждённые исправления только после сверки `git status`, фиксирует их в `PAIR.md` и передаёт Claude.
- Историю исходных статусов и личные браузерные статусы не смешивать.
