## 1. Зачем

## 2. Контракт (решает Claude, менять только через журнал)

Команды, одна на сценарий:

    python tools/ui_snapshots.py check      # run + compare с базой; код выхода 0 — совпало, 1 — расхождение, 2 — ошибка инструмента
    python tools/ui_snapshots.py run        # только снимки и геометрия в tmp/ui-snapshots/<UTC-время>/
    python tools/ui_snapshots.py compare    # сравнить последний run с docs/ui/baseline/
    python tools/ui_snapshots.py baseline   # принять текущий run как базу (только по решению Claude)

Артефакты в `tmp/ui-snapshots/<run>/`: `shots/*.png`, `geometry.json`, `compare.json`, `diff/*.png` (только при расхождении), `report.md`.
База `docs/ui/baseline/` коммитится (PNG маленькие, около 20–40 КБ на сценарий).

Окно: основное 1400×860 и минимальное 1000×600 (проверка обрезки строки «Оповещение» и фильтра).

Сценарии, минимум:
- `tabs-search`, `tabs-chat`, `tabs-map` (вкладки);
- `map-100`, `map-125`, `map-150` (карта, минимум три масштаба, см. п. 4);
- `settings-open`, `settings-closed`;
- `header-idle`, `header-counters` (статус-чип и счётчики).

Опционально позже: окно «Найдено в чате!», подсказка предмета.

## 3. Детерминированность и безопасность данных

- Все входные данные — из временной папки: `Chat.log` с фиксированными строками (время `2026.10.10 18:01:07` и т. п.),
  временный `config.json`. Никогда не читать и не писать `config.json`, `data/`, `client_extract/`, реальный `Chat.log`.
- Во временной конфигурации: `game_check: false`, `reduce_motion: true`, уведомления и тосты выключены (звука и окон не должно быть).
- Рабочая папка на время прогона — временная; после прогона артефакты остаются только в `tmp/ui-snapshots/`.
- Окно снимать через `PrintWindow` с флагом клиентской области (как в скрипте-помощнике из сессии Claude, но код переносится в репозиторий).
  Заголовок окна в снимок не входит.
- Перед снимком: несколько `root.update()` и короткая пауза, иначе геометрия (`bbox`) нулевая.
- Два прогона одного коммита обязаны дать 0 различающихся пикселей. Если нет — найти источник шума и замаскировать его
  (маски задаются в одном месте в коде инструмента и перечисляются в отчёте).

## 4. Масштабы

- 100 %, 125 %, 150 % эмулируются Tk-масштабом: `root.tk.call("tk", "scaling", factor)`, где `factor` = исходный масштаб, умноженный на 1,0 / 1,25 / 1,5.
- Это не то же самое, что системный DPI Windows. Отчёт обязан писать: «эмуляция Tk-масштаба; системный DPI 125/150 % проверен вручную / не проверен».
- Реальная проверка системного DPI — отдельный ручной шаг, в инструмент не входит.

## 5. Сравнение

Геометрия (по именованным виджетам: вкладки, Start, статус-чип, счётчики, лента, список предметов, холст карты):
- прямоугольник каждого виджета в координатах окна; допуск ±1 px;
- текст не обрезан: запрошенная ширина (`winfo_reqwidth`) не больше выделенной, для вкладок и кнопок;
- соседние контролы шапки не перекрываются.

Изображение:
- пиксель считается различающимся, если максимум по каналам разницы больше 16;
- сценарий проходит, если доля различающихся пикселей меньше 0,2 % (порог калибруется по двум прогонам одного коммита, см. п. 3);
- маски динамических областей (таймеры, мигание) не участвуют в сравнении.

Отчёт (`report.md`): таблица сценариев с результатом, долей различий, отклонениями геометрии и путями к diff.
