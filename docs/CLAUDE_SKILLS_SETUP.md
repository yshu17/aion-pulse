Актуальный аудит совместимости с Codex, реального обнаружения и статуса плагинов: [CODEX_CLAUDE_SKILLS_AUDIT.md](CODEX_CLAUDE_SKILLS_AUDIT.md). Ниже сохранён первоначальный срез подготовки четырёх скиллов; часть сведений об установке изменилась позднее 12.10.

## Где находятся и как подключаются

Claude Code обнаруживает проектные навыки в `.claude/skills/<name>/SKILL.md` по [официальному формату Skills](https://code.claude.com/docs/en/skills). Отдельная установка не нужна: открыть корень этого проекта в Claude Code, начать новый сеанс, проверить список навыков и вызвать `/project-master-planner`, `/application-ui-ux-designer`, `/application-software-architect` или `/application-motion-designer`. Если Claude предлагает навык автоматически, сначала сверить его назначение с задачей. Каждая папка содержит `references/` с подробным локальным контрактом; внешних runtime-зависимостей нет.

Примеры:

```text
/project-master-planner Разложи новую настройку уведомлений по существующим планам с ID, зависимостями и критериями готовности.
/application-ui-ux-designer Оцени панель карты на узком окне и предложи исправление перекрытия подписей.
/application-software-architect Сравни два способа атомарно сохранять config.json без переписывания приложения.
/application-motion-designer Опиши раскрытие вложенных задач в HTML с отменой и reduced motion.
```

## Четыре новых проектных скилла

| Скилл | Вход, результат и граница |
|---|---|
| `project-master-planner` | Из запроса, кода, `PAIR.md` и пяти планов делает последовательность задач с ID, зависимостями, критическим путём, рисками и проверяемой готовностью. Поддерживает сортировку, «НОВОЕ», дату и MASTER через существующие генераторы. Не создаёт шестой план и не считает личный статус браузера командным. |
| `application-software-architect` | Анализирует границы модулей, состояние, файлы, фоновые операции, ошибки и варианты решения. Для значимых изменений готовит C4/Mermaid и ADR с миграцией и откатом. Решение утверждает Claude. |
| `application-ui-ux-designer` | Сверяет реальную Tk/HTML поверхность и тему; предлагает компоновку, состояния, навигацию, доступность, масштаб Windows и мобильную читаемость. Существенное предложение содержит проблему, решение, причину, результат и проверку. |
| `application-motion-designer` | Проектирует движение Tk и HTML с токенами времени, отменой таймеров, ограничением повторов, `reduce_motion` / `prefers-reduced-motion` и проверкой производительности. Motion/GSAP не обязательны. |

Процесс для большой функции: **Planner → Architect → UI/UX → Motion → Planner → реализация Claude/Codex → проверка**. Для локальной исправленной кнопки достаточно нужного скилла и обычных правил проекта. Конфликт между рекомендациями скиллов разрешается так: запрос пользователя и `PAIR.md`/`AGENTS.md` → текущий код и токены → проектные навыки → общие внешние советы. Архитектурный контракт утверждает Claude. Перед записью каждый агент проверяет `git status`, работает в отдельном worktree/ветке при параллельной разработке и передаёт изменения через коммит/документацию; чужую незавершённую работу не перезаписывает.

С 12.10 есть отдельные DRAFT-01…06 в `docs/feature-drafts.json`. Они ждут дальнейшей работы этих четырёх навыков Claude и решения владельца; наличие черновика не утверждает техническое решение или разработку.

## Проверка и ограничения

Статический контроль охватывает структуру четырёх папок, YAML metadata, уникальность имён, локальные ссылки, запрет опасных автоматических действий и четыре сценария из задания: план новой функции с зависимостями/диаграммой; улучшение существующей панели; архитектурный анализ модуля без переписывания; раскрытие вложенного блока с reduced motion. Проверка оценивает наличие и непротиворечивость инструкций, **не реальное качество ответа Claude**. Фактический вызов навыков в Claude Code, автоматическая активация и рендер результата не проверены из-за лимита токенов.

Результат 12.10: **4/4** структуры/frontmatter и **6/6** локальных ссылок прошли; **4/4** статических сценария прошли. Производные планы пересобраны, `python tools/check_plans.py` — **100 задач, 5 страниц, OK**. Штатный `quick_validate.py` из Codex skill-creator потребовал отсутствующий `PyYAML` и не запустился; пакет ради проверки не устанавливался. Поэтому metadata проверены встроенной проверкой обязательных полей и границ frontmatter, а не полноценным YAML-парсером. Поля содержат только простые строковые значения.

После восстановления Claude Code: открыть новый сеанс из корня, убедиться, что четыре команды доступны, пройти четыре примера выше на копии задачи без записи в рабочие файлы, сверить применённые инструкции и разрешить замечания. Затем обновлять навыки только при изменении стека/планового контракта; вносить правки локально, снова проверить ссылки и сценарии, записать результат в `PAIR.md`. Не обновлять внешние плагины автоматически.
