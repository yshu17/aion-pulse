# ADR-001. Переносимый пакет ядра: центр уведомлений и чат-лог

Статус: **предложение**, решение за Claude после утверждения пользователем. Дата: 13.10.2026.

## 1. Контекст

Пользователь решил переносить функции в игровой лаунчер на Tauri 2 + React (см. `docs/ARCHITECTURE_MAP.md`, `docs/CORES.html`).
Нужно выделить ядро, которое не тянет Tk и может быть переписано или запущено отдельно.

Проверено по коду (13.10.2026):

| Модуль | Строк | Tk | Внешние зависимости |
|---|---|---|---|
| notify_center | 221 | нет | stdlib (collections, dataclasses, time) |
| alert_bridge | 66 | нет | notify_center |
| notify_settings | 27 | нет | нет (принимает cfg, center, manager как объекты) |
| tailer | 110 | нет | stdlib (logging, os, re, datetime) |
| parser | 186 | нет | **catalog** → `data/map_names.tsv`, `data/quest_names.tsv` через `resource_root()` |
| matcher | 106 | нет | parser |
| series | 71 | нет | matcher, parser |
| alerts | 68 | нет | parser |

Итого 7 модулей без Tk, 879 строк. Тесты на них: 25 (parser) + 21 (matcher) + 8 (series) + 7 (alerts) + 6 (notify_center) + 6 (alert_bridge) + 5 (notify_settings) + 11 (tailer) = 89 (по имени файла).

Вызывающие экраны (Tk): `app.py` (8 импортов), `feed.py`, `toasts.py`, `alarm.py`, `allchat.py`, `textview.py`, `itemlist.py`, `mapview.py`, `poi.py`, `notify_tab.py`. Все они импортируют ядро, ядро их не импортирует — граница чистая.

**Скрытая зависимость** (найдена проверкой): `parser` берёт имена карт и квестов из `data/` через `catalog.resource_root()`. В переносимом пакете путь к данным должен передаваться параметром, а не вычисляться.

## 2. Варианты

**A. Оставить как есть, только объявить границу.** Ничего не двигаем. Добавляем тест «ядро не импортирует tkinter». Минимум риска. Для лаунчера ядро копируется вручную и поддерживается в двух местах.

**B. Выделить пакет `watcher/core/` (или отдельный каталог `core/`) с 7 модулями, без импортов из `watcher/` вне пакета.** Данные передаются параметрами (`parser` получает `names` словарь). Экраны импортируют из `core`. Перенос в лаунчер — копированием каталога или подключением как пакета.

Выбираю **B**, но с условием: пакет физически не переносится в этом шаге, только выравнивается граница. Это безопасно для exe и тестов.

## 3. Решение (предлагаемое)

1. Новый пакет `core/` внутри репозитория (не `watcher/`), модули: `notify_center`, `alert_bridge`, `notify_settings`, `tailer`, `parser`, `matcher`, `series`, `alerts`.
2. Контракт `parser`: функции принимают словари имён (`map_names`, `quest_names`) аргументами. Загрузку из TSV делает `watcher/` (тонкая обёртка). Дефолт — пустой словарь, поведение без имён сохраняется (как сейчас при отсутствии файла).
3. Импорты: `core/*` импортирует только stdlib и `core/*`. Проверка тестом: AST-обход, запрет `tkinter` и `watcher.` внутри `core/`.
4. `watcher/` оставляем на месте; старые пути импорта (`watcher.parser`, …) сохраняем как re-export, чтобы не править 15 файлов в одном шаге.

## 4. Контракт (входы/выходы)

| Функция/класс | Вход | Выход | Состояние |
|---|---|---|---|
| `parse_line(line, item_names, map_names, quest_names)` | строка лога | `ChatLine` / `ChatMessage` / None | нет |
| `Matcher.check(msg, now)` | `ChatMessage`, monotonic time | список совпадений | cooldown по игроку |
| `SeriesTracker.record/is_silent` | сообщение, совпадения, время | bool / None | история серий |
| `AlertTracker.add/accept/expire` | сообщение, время | id тревоги / список id | ожидающие тревоги |
| `NotificationCenter.notify(...)` | источник, вид, заголовок, текст, действия | `Notification` / None | очередь, история, счётчики |
| `AlertBridge.chat_match / toast_accepted / alerts_done / game_running` | id тревог, записи чата | `Notification` / список id | связь тревога ↔ уведомление |
| `notify_settings.apply(cfg, center, manager)` | конфиг с полями `notify_*` | — | меняет правила центра |
| `LogTailer.read_new()` | путь к файлу | список строк (bytes → str) | позиция в файле |

Часы: ядро принимает `clock` параметром (`monotonic` по умолчанию). Тесты подменяют.

## 5. Владельцы состояния и таймеры

- Состояние `NotificationCenter`, `AlertTracker`, `SeriesTracker`, `Matcher` — в памяти процесса, владелец `app.py`.
- Таймеров в ядре нет. Repeat и snooze центра проверяются вызовом `tick()` из таймера программы (сейчас 33 мс у тостов, 1 с у `_tick`). В лаунчере — свой таймер, ядро не меняется.
- `LogTailer` — синхронный, читает при вызове. Фоновый поток — владелец `app.py`.

## 6. Риски

- **Регрессия импортов.** 15 файлов импортируют `watcher.parser` и др. Mitigation: re-export в старых местах, полный прогон 482 тестов.
- **Данные.** Если перенос `parser` сломает загрузку имён карт, будут пустые «Место · …». Mitigation: тест на `parse_line` с именами и без.
- **exe.** `build_exe.bat` собирает `watcher/` через `main.py`. Новый пакет `core/` должен попасть в сборку: проверить, что PyInstaller его находит (импорт идёт через `watcher.core`, а не через путь).
- **Работа Codex.** Ветки `codex/*` могут править эти модули. Mitigation: перед шагом — проверить `git status` и ветки, не трогать чужие незакоммиченные файлы.

## 7. Миграция (шаги, каждый — отдельный коммит)

1. **Тест границы (без переноса).** Добавить `tests/test_core_boundary.py`: AST-проверка, что 8 модулей не импортируют `tkinter`/`watcher.(app|feed|toasts|...)`. Сейчас тест пройдёт — это фиксация текущего состояния. Откат: удалить файл.
2. **`parser` без `catalog`.** Ввести параметры `map_names`, `quest_names` в `parse_line` и `places_in`; `watcher` передаёт их явно. Старое поведение — через функции-обёртки. Тесты: 25 текущих + новый на пустые словари. Откат: вернуть `_load_map_names`.
3. **Пакет `core/`.** Переместить 8 модулей в `core/` с `git mv`, оставить `watcher/<имя>.py` с `from core.<имя> import *`. Тесты: все 482 + граница. Откат: `git revert` коммита.
4. **Проверка exe.** Пересборка в `build\next\` (не в основную папку, пока программа запущена), запуск, сверка окна. Откат: не публиковать.
5. **Документы.** Обновить `docs/ARCHITECTURE_MAP.md` и `docs/CORES.html` (карта ядра). Пересобрать планы (`tools/build_plans_site.py`), запись в `PAIR.md`.

Перенос в лаунчер — отдельный ADR-002 после шага 5, по пункту `DRAFT-05.7` (вкладки Chat Watcher).

## 8. Критерии проверки

- `pytest` — 482+ зелёные, граница — зелёная.
- В `core/` ни одного импорта `tkinter` и `watcher.`.
- Тесты `parser` проходят без файлов данных (словари передаются).
- Сборка exe проходит, программа открывается, совпадение в чате даёт тост.

## 9. Откат

Каждый шаг — отдельный коммит. Откат — `git revert` одного коммита. Текущий exe не трогаем до шага 4. Ветка `feat/chat-watcher` остаётся рабочей на любом шаге.

## 10. Что не входит в этот ADR

- Перенос в лаунчер (ADR-002).
- Перенос Tk-экранов (`app.py` и др.) — отдельное решение.
- Изменение формата `config.json`, `schedule_custom.json`, `data/`.
