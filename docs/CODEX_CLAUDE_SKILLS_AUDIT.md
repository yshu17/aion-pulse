Проверка структуры: четыре разных значения `name`, четыре `SKILL.md`, четыре существующих `references/*.md`. В телах нет обязательного вызова Claude-only `Skill`/`Task` API; упоминание Claude Code задаёт роль Lead Developer. Файлы не копировались и не менялись.

### Адаптация для Codex без второй копии

1. Перед задачей читать `PAIR.md`, `git status --short` и нужный `SKILL.md` вместе с его `references/`. `AGENTS.md` уже указывает на эти четыре файла.
2. Codex использует свои доступные средства для чтения, редактирования и проверки. Указания о Claude Code или его slash-командах трактовать как цель процесса, а не как требование иметь инструмент Claude. Не придумывать эквивалент отсутствующему инструменту.
3. Следовать пользовательскому поручению и закреплённой в `PAIR.md` зоне ответственности. Если скилл предлагает архитектурное изменение, передать Claude вариант и ADR; реализацию начинать после согласованного контракта.
4. При параллельной работе не редактировать чужие незавершённые файлы; использовать отдельные ветки/worktree по `docs/AI_COLLABORATION.md`. После задачи обновить план и журнал.
5. Общие источники качества: `PAIR.md`, `docs/AI_COLLABORATION.md`, эти четыре скилла и их `references/`. Инструменты, зависящие от агента, остаются в его собственном профиле.

**Единый источник:** оставить четыре проектных скилла в `.claude/skills/` и ссылаться на них из `AGENTS.md`, как уже сделано. Codex официально ищет нативные навыки в `.agents/skills/`, поэтому текущий маршрут даёт **ручное применение**, а не slash/автоматическое обнаружение. Возможную directory junction `.agents/skills/<name>` → `.claude/skills/<name>` сначала проверить в отдельной тестовой копии и новом сеансе Codex; не создавать её в общем рабочем дереве, пока не подтверждены обнаружение на Windows, поведение в Git/worktree и отсутствие дублей в селекторе. Для общего качества нативное обнаружение необязательно.

## Superpowers, UI/UX Pro Max и недостающее

- **Superpowers:** в текущей сессии Codex доступны инструкции 6.4.2; в Claude Code установленная запись 6.4.1 сейчас сообщает ошибку загрузки. Сначала повторить проверку Claude в обычной среде. Переустановку/обновление не выполнять без согласования. Не копировать плагин в проект.
- **UI/UX Pro Max:** один экземпляр найден в `~/.claude/skills/` и доступен Claude Code. Для Codex это обычный читаемый файл, но не нативно обнаруженный скилл. При UI работе Codex сначала применяет проектный `application-ui-ux-designer`, затем при необходимости читает глобальный справочник; специфичные web/React советы не заменяют Tk токены. Отдельная установка для Codex сейчас не требуется.
- **Что может пригодиться позже:** визуальная проверка реального Tk окна на нескольких DPI и размеров, проверки клавиатуры/контраста; автоматическая проверка UI с Playwright имеет смысл только для HTML планов. Это задачи процесса, а не причина устанавливать новые плагины. `frontend-design` и `pyright-lsp` рассматривать при появлении конкретной потребности. Новые сторонние инструменты и глобальные настройки — только после согласования с владельцем.

## Проверка обнаружения после изменений

1. В новом Claude Code сеансе из корня проекта проверить четыре `/application-*`/`/project-master-planner` и Superpowers; текущая ошибка кэша делает последнюю проверку открытой.
2. В новом Codex сеансе проверить каталог навыков: четыре проектных имени сейчас в нём **не перечислены**, но доступны через `AGENTS.md` и прямое чтение файлов. Если решено использовать junction, проверить появление каждого имени ровно один раз.
3. На двух коротких задачах без записи проверить, что оба агента ссылаются на один и тот же файл скилла и одинаковые правила ID, статусов, проверки и передачи; Claude сохраняет право утверждать архитектуру.
4. После изменения файлов скиллов проверить YAML frontmatter, уникальность `name`, локальные ссылки и живое применение в новых сеансах обоих агентов.
