# Telegram: живой чат в группу + уведомления поиска в личку — логика и план

Статус: **ждёт команды «делаем».** Готова и покрыта тестами только логика пачек
(`watcher/tgbatch.py`, `tests/test_tgbatch.py`). Отправки в Telegram ещё нет.

Один бот, два адресата:

| Куда | Что | Как часто |
|------|-----|-----------|
| **Группа** (`tg_group_chat_id`) | живой чат — то же, что вкладка «Весь чат» | пачками, ≤ 20 сообщений/мин |
| **Личка** (`tg_alert_chat_id`) | совпадения поиска (как строки в ленте «Поиск») | сразу, по одному, со звуком |

Каждое направление включается своей галочкой. Можно только группу, только личку или оба.

Коротко:

- **Живой чат уходит в группу.** Бота добавляют в группу, и он пишет туда.
- **Совпадения поиска и уведомления уходят в личные сообщения.** Для этого один раз написать
  боту `/start`, чтобы он мог писать первым.
- **Настройка:** в `config.json` два поля — `tg_group_chat_id` (группа) и `tg_alert_chat_id`
  (личка), и галочки, что куда отправлять (`tg_group_enabled`, `tg_alert_enabled`).

## Как это будет работать

```
Chat.log ──► Aion Chat Watcher ──┬─► фильтр «Весь чат» ──► ChatBatcher ──► отправщик ──► группа
                                 └─► поиск (совпадения) ─────────────────► отправщик ──► личка
```

1. Программа читает `Chat.log` в реальном времени (как сейчас).
2. **Группа:** строки проходят тот же фильтр, что и вкладка «Весь чат»: Поиск группы, общий,
   личные, группа, легион; «Информация и уведомления» — если включена галочка во вкладке.
   Трансляция идёт, пока включена галочка «Чат в группу», независимо от Start и вкладки.
   История за прошлые минуты не отправляется, только новое. Без звука (`disable_notification`).
3. **Личка:** каждое совпадение поиска (после Start, история не шлётся — как и звук) уходит
   отдельным сообщением сразу, со звуком. Найденное слово / предмет выделены жирным.
4. Отправка в отдельном потоке — окно программы не подвисает.

## Логика пачек для группы (`ChatBatcher`, готово)

Telegram пускает бота примерно на **20 сообщений в минуту в одну группу**. Поэтому:

- **Обычно — 2 строки чата в 1 сообщении**, отправка **сразу**, как только пришла вторая строка.
- Одиночная строка ждёт пару **3 с**, потом уходит одна.
- Скользящее окно 60 с считает отправленные сообщения. Когда в нём уже **18** —
  переход на **4 строки в 1 сообщении** (запас на 19-е и 20-е).
- **Больше 20 сообщений за любые 60 с не уходит никогда.** Если лимит выбран, строки ждут в очереди.
- Последнее свободное место в минуте (20-е сообщение) забирает **всю очередь**, сколько влезет
  в 4096 символов, — так очередь не растёт, строки не теряются и не меняют порядок.
- Когда за минуту отправлено меньше **10** — обратно на 2 строки (без «дребезга» между режимами).
- Очередь — до 500 строк; при переполнении выкидываются самые старые (счётчик `dropped`).

Пропускная способность: обычный режим — до ~40 строк/мин почти без задержки; в пике 18×2 + 4 +
одно «большое» сообщение до 4096 символов (≈ 40–60 строк чата) — всё равно без потерь.

Все числа — параметры `ChatBatcher(normal=2, compact=4, limit=20, warn_at=18, relax_below=10,
flush_after=3.0)`, их можно поменять.

### Пример сообщения в группе (режим 2 строки)

```
21:43:17 [3.Поиск группы] Seller: WTS [Клинок Рудры] 5кк
21:43:18 [Группа] Tiyamate: идём в пхасу
```

### Пример уведомления в личку

```
🔔 21:43:17 Seller: WTS <b>[Клинок Рудры]</b> 5кк
```

## Что понадобится от тебя (один раз)

1. **@BotFather** → `/newbot` → имя → получить **токен** вида `123456:ABC...`.
2. Для группы: создать закрытую группу, добавить туда бота, написать в группе любое сообщение.
3. Для лички: открыть бота и нажать **Start** (`/start`) — иначе бот не может писать первым.
4. Вставить токен в программу, нажать «Найти чаты» — программа через `getUpdates` покажет
   найденные группу и личку, выбрать нужные.

## Безопасность и ограничения

- **Токен = пароль от бота.** Хранится только в `config.json` рядом с exe (не в git, не в exe).
  Не пересылай exe вместе с `config.json`.
- Бот пишет только в два выбранных чата.
- В группу уходят сообщения **других игроков** — группа должна быть закрытой.
- Нет связи → строки копятся (до 500), уйдут при восстановлении; в статусе «Telegram: нет связи».
- `429 Too Many Requests` → ждём `retry_after`, потом отправляем (лимит пачек это почти исключает).
- Личка: Telegram допускает ~1 сообщение/с в один чат — при всплеске совпадений короткая очередь.
- Только стандартная библиотека Python (`urllib`), без новых зависимостей.
