# Схема задачи планов (единый стандарт, 12.10.2026)

Источник истины — генераторы из `tools/`. Страницы планов и MASTER PLAN строятся из одного набора данных
(`docs/plan-model.json`). Ручная правка HTML-страниц не сохраняется при пересборке.

## 1. Статусы (восемь, утверждено пользователем 12.10.2026)

| Ключ | Надпись | Смысл |
|---|---|---|
| `planned` | Запланировано | открытая задача по умолчанию |
| `research` | Исследование | изучение перед решением (этапы черновиков начинаются здесь) |
| `doing` | В работе | делается |
| `blocked` | Заблокировано | ждёт того, что назван в задаче |
| `review` | На проверке | работа сделана, отметки пользователя ещё нет |
| `done` | Выполнено | **только отметкой** (чекбоксом) |
| `deferred` | Отложено | отложено по решению |
| `cancelled` | Отменено | не выполнено, из прогресса исключается |

Словарь живёт в `tools/plan_states.py`. Старое значение `todo` читается как `planned`.
Исходники планов пока хранят `todo / doing / done`: сборка переводит их при загрузке.

### Правило чекбокса (утверждено)
- Отмеченная задача — `done`. Не отмеченная задача не `done`, даже если работа сделана.
- Сделанная, но не отмеченная задача — `review` («На проверке»): ждёт отметки пользователя.
- Снятие отметки с `done` переводит задачу в `review`, а не в `planned`.
- Список статусов не содержит «Выполнено»: выставить его можно только отметкой.
- Отменённая задача не считается выполненной и не входит в знаменатель прогресса.

## 2. Приоритеты

Шкала: `Critical`, `High`, `Medium`, `Low`. Пустое значение показывается как «Не определён».
Старые `P0–P3` переводятся: P0 → Critical, P1 → High, P2 → Medium, P3 → Low (утверждено).
Приоритет не назначается автоматически: если его нет в источнике, задача показывается как «Не определён».

## 3. Поля задачи

| Поле | Обязательность | Источник |
|---|---|---|
| `key` (ID), `id` (номер) | обязательно | исходный план, ID не меняется |
| `title`, `text` | обязательно | исходный план |
| `plan` (план/раздел) | обязательно | генератор |
| `status` | обязательно | исходный план, нормализуется сборкой |
| `priority` | необязательно | исходный план; пусто = «Не определён» |
| `added_at` (дата создания) | если известна | `docs/plan-task-meta.json` |
| `changed_at`, `history` | если были | `plan-task-meta.json`, журнал изменений |
| `who` (исполнитель текстом), `agent` (claude / codex / joint / user) | обязательно для открытых задач | `docs/plan-ai-tools.json` |
| `reviewer` (проверяющий) | для открытых задач | `plan-ai-tools.json` |
| `skills` (основной и дополнительные, с назначением) | для открытых задач | `plan-ai-tools.json` |
| `handoff` (передача) | для задач Codex | `plan-ai-tools.json` (`ready`, `in-progress`, `review`, `integrate`, `blocked`, `n/a`, …) |
| `branch` (ветка) | если назначена | `plan-ai-tools.json` |
| `dependencies_text`, `depends_on` | если есть | исходный план / `plan-ai-tools.json` |
| `parent` (родитель, подзадачи) | если есть | `plan-ai-tools.json` (сейчас ни у одной задачи) |
| `done` (критерии готовности) | для открытых задач | `plan-ai-tools.json` |
| `tests` | если заданы | `plan-ai-tools.json` |
| `files` (разрешённые файлы) | если заданы | `plan-ai-tools.json` |

Поле поддерживается схемой, но это не значит, что значение есть: отсутствующее значение не заполняется выдуманным.

## 4. Даты

- Задачи без записанной даты создания получают **08.10.2026** — дату, которую выбрал пользователь 12.10.2026.
  В истории задачи записано, что дата проставлена решением, а не найдена в источнике.
- Этапы черновиков получают дату набора черновиков (`feature-drafts.json`, `12.10.2026 01:44`).
- Новые задачи получают текущую дату и становятся `latest` (бейдж NEW, только у открытой задачи).
- История (`history`) не удаляется и не переписывается задним числом.

## 5. Номера и ID

- ID (`map:N`, `ui:N`, `sn:SN-N`, `tg:N`, `draft:DRAFT-NN.N`) постоянный. Существующие номера не меняются.
- Новый пункт получает следующий номер и попадает наверх. Больший номер выше меньшего.
- Ключи из `known_keys` не получают NEW. Ключи черновиков добавляются в каталог без NEW.

## 6. Прогресс

- Считается по уникальным ID: `выполнено / (всего − отменено)`.
- Каждая задача учитывается один раз, даже если видна в MASTER PLAN и в своём плане.
- Счётчики: выполнено, в работе, на проверке, заблокировано, запланировано, исследование, отложено, отменено.
- Проценты не выдумываются: считаются из статусов.

## 7. Исполнители и Skills

- Исполнитель: Claude Code (архитектура, контракты, ревью, интеграция), Codex (делегированные модули, UI, тесты, отладка),
  совместно, пользователь. Смена исполнителя фиксируется полем `reassigned` с датой и причиной.
- Skills: один основной и не более нескольких дополнительных, с назначением каждого. Статус доступности —
  `установлен` или `NOT VERIFIED`, а не выдуманное значение. Реестр — `docs/plan-ai-tools.json`.

## 8. Правила для новых планов

Новый план не пишет собственную карточку. Он:
1. Даёт задачи в общий источник (`plan-model.json` через генератор).
2. Получает общую карточку и общие фильтры через `tools/plan_shared.py`.
3. Попадает в MASTER PLAN и в общую навигацию через `tools/plan_common.py`.
