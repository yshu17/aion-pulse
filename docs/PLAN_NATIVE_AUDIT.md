# Аудит нативных списков и план миграции (12.10.2026) — на утверждение

Решение пользователя: общая карточка Task Card и единый источник данных — основная архитектура всех планов.
Нативные списки не удалены. Этот документ — аудит их функций и данных и безопасный план переноса. Ничего разрушительного не выполнено.

Общая карточка (`tools/plan_shared.py`) уже есть на каждой из 12 страниц рядом с нативным списком. Поэтому сейчас задачи показываются
дважды (нативный список и сворачиваемая панель «Общие задачи»). Это исключается на шаге 3 плана.

## 2. Данные пользователя и ключи

| Ключ `localStorage` | Что внутри | Кто пишет | Кто читает |
|---|---|---|---|
| `aion-shared-plan-ledger-v1` | `{schema_version, statuses{ключ → статус}, history[]}` | общая карточка | общая карточка |
| `aion-ui-ux-plan-status-v1` | `{номер → todo/doing/done}` | нативный список UI/UX и общая карточка (зеркало) | UI/UX, MASTER |
| `aion-telegram-plan-status-v1` | то же для Telegram | нативный Telegram и общая карточка | Telegram, MASTER |
| `aion-master-plan-filters-v1` | значения фильтров MASTER | MASTER | MASTER |
| `aion-backup-last-v1` (новый) | состояние до последнего импорта | общая карточка | кнопка «Откатить импорт» |

Приоритет чтения статуса: журнал общей карточки → старый нативный ключ → значение из исходника. Поэтому отметки, сделанные ранее на нативных
страницах, не теряются: они читаются при отрисовке. Общая карточка зеркалирует свои отметки в старые ключи, пока нативные списки существуют.

### Origin браузера
`localStorage` привязан к origin: страница, открытая с диска (`file://`), с локального сервера (`http://localhost:…`), из артефакта на claude.ai и со
сторонней страницы, имеют разные, не пересекающиеся хранилища. Отметки не переходят между ними сами. Единственный путь переноса — экспорт и импорт.
Проверено в браузере 12.10: круг «экспорт → очистка хранилища → импорт → откат» на одном origin работает; перенос между разными origin по
определению возможен только файлом.

## 3. Найдено при аудите и уже исправлено (безопасные подготовительные изменения)

1. **Импорт отбрасывал новые статусы.** Проверка допускала только `todo/doing/done`. Резервная копия после перехода на восемь статусов
   теряла бы «На проверке», «Заблокировано» и другие. Исправлено: импорт принимает всё, что есть в словаре, старое `todo` читается как «Запланировано».
2. **Экспорт не содержал старые ключи.** Исправлено: файл содержит поле `native` со значениями старых ключей. Импорт восстанавливает их.
3. **Зеркало писало новые статусы в старый ключ.** Старые страницы их не знают. Исправлено: в старый ключ пишутся только `todo/doing/done`.
4. **Нет отката импорта.** Исправлено: перед импортом состояние сохраняется (`aion-backup-last-v1`), кнопка «Откатить импорт» возвращает его.

Проверка: полный круг в браузере (статусы `review` и `blocked`, старый ключ, откат), без ошибок в консоли.

- Работа нативных страниц со старой версией ключей на других браузерах (Safari, Firefox): проверено только в браузере встроенной панели.

### Данные пользователя
Автоматически ничего не мигрировано. Перенос запускается кнопкой «Перенести старые отметки» в браузере пользователя: показывает, что переносится и
каждый конфликт, по умолчанию конфликт остаётся как в общем журнале, нужно подтверждение резервной копии, откат — «Откатить».
Проверено на тестовых данных: копирование, конфликт с выбором, идемпотентность (повторный запуск: «Переносить нечего»), откат, неизменность старых ключей.
Между origin ничего не переносится: только явные «Экспорт» и «Импорт».

### Что скрыто
Старые списки UI/UX (заголовок «Этапы», боковая панель этапов, список задач, фильтры), Telegram (то же) и MASTER («Все шаги» с фильтрами) —
по умолчанию скрыты. Адрес с `?native=1` показывает их снова. Кнопка «Сбросить» в шапке UI/UX и Telegram скрыта вместе со списком.
Переключатель: `HIDE_NATIVE_LISTS` в `tools/plan_shared.py` (False и пересборка возвращают старый вид на всех страницах).
Состояния зафиксированы тегами: `plan-native-visible` (до скрытия) и `plan-native-hidden` (после).

### Риски

- Страницы проверены в одном браузере (встроенная панель); независимая проверка — задача `ui:44` (Codex).
