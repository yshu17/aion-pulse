## 4. Отсутствующие и неоднородные элементы

1. **Черновики (6 страниц) — отдельный стиль.** Нет поиска, фильтров, статусов, прогресса, сохранения состояния, общего каркаса. Самая большая разница.
2. **Статусы.** В данных три значения (`todo`, `doing`, `done`). Нет «На проверке», «Заблокировано», «Отложено», «Отменено», «Исследование». Частично это есть в другом поле: `handoff` (`review` и `blocked` для 7 задач, `in-progress` для 2). Два разных поля описывают одно и то же.
3. **Приоритеты.** Используются P0–P3, а не Critical/High/Medium/Low. Для 58 задач приоритета нет. Сопоставление возможно, но выбрать шкалу должен ты.
4. **Даты.** Для 98 задач дата создания не записана. Правило «не придумывать задним числом» (`PAIR.md`, правило 11) не позволяет её восстановить. Показывать «Не определено».
5. **Чекбоксы.** Нигде нет. Выполнение задаётся селектом статуса. Требование «чекбокс и статус — одно состояние» пока не выполнено ни в одном плане.
6. **Подзадачи.** Поля `parent` нет в данных ни у одной задачи. Вложенные пункты в MASTER не моделируются.
7. **Диаграммы и timeline.** Аналитических диаграмм нет. Зависимости показаны текстом.
8. **Skills.** Реестр 20 позиций. Не в реестре: `frontend-design` (плагин включён 12.10, проверить после перезапуска сессии), `enterprise architecture`, общий `software architect` (не установлены). Motion / GSAP не установлены по решению 12.10. Наличие «NOT VERIFIED» для Кодекса — честное состояние.
9. **Прогресс.** Процент считается по статусам `done` из 101 уникального ID. Правило «не считать дважды» соблюдено: каждый ID один раз. Формулы для разных разделов не документированы.

## 6. Решения, которые нужны от тебя (Этапы 2–4)

1. **Набор статусов.** Оставляем три текущих и добавляем `review` и `blocked` из `handoff`, или переходим на предложенные восемь? Сопоставление: `todo` = Запланировано, `doing` = В работе, `done` = Выполнено. Для `review` и `blocked` предлагаю брать значение из `handoff`, а не заводить второе поле.
2. **Шкала приоритетов.** Предлагаю сопоставление P0 → Critical, P1 → High, P2 → Medium, P3 → Low, пустое → «Не определён». Автоматических назначений не делаю.
3. **Черновики.** Переводим 6 страниц на общий каркас (поиск, фильтры, статусы, сохранение) или оставляем отдельный формат до утверждения функций? Рекомендую перевести: это единственная несогласованность с остальными планами.
4. **Чекбокс.** Чекбокс = статус `done`, отменённая задача в статус `done` не попадает. Подтверди правило.
5. **Даты.** Для задач без даты показываем «Не определено». Восстанавливать даты по истории git не предлагаю: это придуманные значения.
