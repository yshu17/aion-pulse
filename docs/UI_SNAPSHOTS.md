# Визуальные снимки Aion Chat Watcher (ui:43)

Инструмент Windows-only: снимки клиентской области окна делает Win32 `PrintWindow` с флагами `PW_CLIENTONLY | PW_RENDERFULLCONTENT`. Требуются установленный Python, Tkinter и Pillow из текущего проекта. Запускать из корня отдельной рабочей копии:

```powershell
python tools/ui_snapshots.py run
python tools/ui_snapshots.py compare
python tools/ui_snapshots.py check
```

- `run` снимает 10 фиксированных состояний при **1400×860 и 1000×600** (20 снимков), записывает `geometry.json`, `manifest.json` и `report.md` в `tmp/ui-snapshots/<UTC-время>-<pid>/`. Последний успешный прогон указывает `tmp/ui-snapshots/latest.json`.
- `compare` сравнивает последний прогон с `docs/ui/baseline/`, добавляет `compare.json`, обновляет `report.md` и пишет `diff/*.png` для различающихся изображений.
- `check` последовательно делает `run` и `compare`.
- `baseline` принимает последний `run` в `docs/ui/baseline/`. **Выполнять только после решения Claude Code о принятии базы**. Команда не перезаписывает существующую базу.

Коды выхода: `0` — совпало или прогон успешно снят; `1` — сравнение нашло отличие; `2` — ошибка инструмента, отсутствие базы или зависание worker. Каждый сценарий запускается в отдельном процессе с ограничением 60 секунд.

Параметры сравнения: `--pixel-channel 16` (пиксель различается при максимуме разницы каналов **больше** 16), `--pixel-fraction 0.002` (сценарий проходит при доле различий **меньше** 0,2 %). Геометрия именованных контролов сравнивается с допуском ±1 px. Обрезанные подписи вкладок и кнопок, а также пересечения контролов шапки дают провал независимо от базы. Динамические маски задаются централизованно в `DYNAMIC_MASKS`; текущая фиксированная фикстура обходится без масок. Маски всегда перечисляются в отчёте.

Фикстура создаёт `Chat.log` и `config.json` в одноразовой папке внутри `tmp/ui-snapshots/<run>/`; после сценария они удаляются. `game_check`, анимации, звук и всплывающие уведомления выключены. Путь, показанный в настройках, фиксирован только для изображения; действующая конфигурация указывает на временный журнал. Код не читает и не меняет рабочие `Chat.log`, `config.json`, `data/` и `client_extract/`.

Карта снимается при масштабах Tk 100 %, 125 % и 150 %. **Это эмуляция Tk-масштаба; системный DPI Windows 125/150 % вручную не проверен.** Для проверки системного DPI Claude и владелец проекта отдельно меняют масштаб Windows и выполняют `check` на соответствующей машине.

## Проверенные ограничения текущей версии приложения

- Приложение само задаёт минимальную ширину **1132 px**. Чтобы проверить контрактный сценарий 1000×600, фикстура после построения интерфейса временно разрешает ширину 1000 px. При этом видна обрезка кнопки «Настройки». Это обнаруженный дефект приложения, а не изменение его файлов инструментом.
- При Tk-масштабе 150 % кнопка «Настройки» также обрезается при 1400×860. Пока Claude не решит этот вопрос в `watcher/`, `check` должен сообщать о провале геометрии. Инструмент намеренно не скрывает обрезку базовой картинкой.
- База `docs/ui/baseline/` ещё требует решения Claude Code. Без базы `compare` и `check` возвращают код `2` с понятным сообщением.

Тест неправильного `(22, 8)` использует реальный `ttk.Notebook` и меняет стиль только внутри тестового процесса: должны отличаться и ширина вкладки, и пиксели. Он не меняет `watcher/theme.py` или базу. Тесты: `python -m pytest -q tests/test_ui_snapshots.py` и полный `python -m pytest -q`.
