# Motion contract: действующее и предлагаемое

## Действующая реализация

- `watcher/theme.py:MOTION`: `fast=120`, `base=200`, `blink=300`, `alarm_blink=500`, `found_blink=3000` мс. Это действующие значения; другие эффекты пока задают время локально.
- `watcher/motion.py`: `tween_color` (обычно 4 шага, проверяет существование виджета), `fade_window` (5 шагов). При добавлении эффектов хранить и отменять идентификаторы `after`, защищать завершение окна. Проверить, не создаёт ли новый цикл таймер после `close`.
- `watcher/mapview.py`: перелёт к точке 4 кадра с интервалом 35 мс и easing-out; найденная точка мигает 3 с по 300 мс. `App.cfg.reduce_motion` переводит перемещение и декоративные эффекты в мгновенное состояние.
- `watcher/toasts.py`: въезд тоста около 220 мс; опрос каждые 33 мс; `reduce_motion` завершает въезд сразу. Тосты и тревога имеют отдельные причины движения.
- HTML планов: CSS/JS без React. Для них использовать `@media (prefers-reduced-motion: reduce)` и не менять личный статус при одном лишь раскрытии карточки.

## Шаблон предложения

| Событие | Состояние до → после | Длительность и easing | Повтор/отмена | Reduced motion | Проверка |
|---|---|---|---|---|---|
| Раскрытие вложенного пункта | закрыт → открыт | предложить после снимка/замера | быстрый повтор завершает предыдущую анимацию | мгновенно открыт | текст не обрезан, фокус сохранён |

Для spring physics, stagger, shared element, SVG и параллакса сначала докажи пользу для конкретного сценария. Укажи цену по кадрам, размеру и доступности. Сохранённые `theme.MOTION` — единственный источник для desktop; HTML-планам можно предложить CSS custom properties, если несколько страниц используют одинаковое время. Рекомендации `motion.dev` и `gsap.com` — справочный материал для веб-поверхности, их JS пакеты не нужны для Tk.
