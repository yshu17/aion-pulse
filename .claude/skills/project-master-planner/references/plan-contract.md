# Контракт пяти планов

## Источники и вывод

| План | Источник задач | Сборка |
|---|---|---|
| Карта | `docs/map-poi-plan.html`, `STEPS3` | мастер-сборщик обновляет общий обзор |
| Расписание | `docs/schedule-notify-plan.html`, `STEPS` | мастер-сборщик обновляет общий обзор |
| UI/UX | `UI_UX_IMPROVEMENT_PLAN.md` | `tools/build_ui_ux_plan.py` |
| Telegram | `docs/telegram-bridge-plan.md` | `tools/build_telegram_plan.py` |
| MASTER | производный `docs/plan-model.json` | `tools/build_master_plan.py` → `docs/index.html` |

`docs/plan-task-meta.json` хранит известные ключи, время добавления, `latest` и историю правок исходников. Примеры ключей: `map:39`, `sn:SN-10`, `ui:42`, `tg:2.2`. Старые ID не переименовывать. Новые шаги карты/расписания добавлять в конец массива, сохраняя номер; представление сортирует их сверху вниз. Дата нового пункта: реальное время Europe/Warsaw в формате `ДД.ММ.ГГГГ ЧЧ:ММ`, без ретроактивного заполнения. В браузере «НОВОЕ» исчезает после `doing` или `done` и переходит к следующему новому пункту. Личные статусы браузера хранятся отдельно в `localStorage` и не подтверждают исходный статус.

Дополнительные концепции пользователя DRAFT-01…06 — отдельный предварительный реестр `docs/feature-drafts.json` с `reviewStatus: DRAFT`. `tools/build_feature_drafts.py` создаёт из него обзор и шесть страниц, на которые ссылается MASTER. Это не шестой утверждённый основной план и не новые задачи в `docs/plan-task-meta.json`: пока Claude не проверит механику и архитектуру, не переносить их в основную очередь и не назначать статус `doing`/`done`. Новые записи черновиков получают постоянный DRAFT-ID, реальную дату и один `latest` для «НОВОЕ» в своём реестре. Античит — подплан лаунчера.

## Проверяемый шаг

Запиши проблему/ожидаемый результат, владельца, зависимости (`plan:ID` когда возможно), исходный статус `todo`/`doing`/`done`, критерии готовности и проверяемое свидетельство: тест, файл, снимок, отчёт или решение пользователя. Если зависимость не подтверждена, укажи как блокер, не подставляй выдуманный ID. Для завершённого шага — что изменено и чем проверено. Важные проблемы и текущая работа — выше свернутых завершённых версий.

## После правки источника

```text
python tools/build_ui_ux_plan.py
python tools/build_telegram_plan.py
python tools/build_master_plan.py
python tools/build_plans_site.py
python tools/check_plans.py
```

Мобильный файл `build/plans_site/` локальный. Перепубликация `claude.ai` — только Claude по `PAIR.md`. Общую проверку кода и планов можно запустить `python tools/check_project.py`. Если изменён только текст `PAIR.md`, пересобери мобильный набор, чтобы его копия не устарела.

## Инструменты разработки (AI Tools & Skills)

`docs/plan-ai-tools.json` — единственный источник рекомендаций: реестр `skills` (название, направление, `source`, доступ Codex) и `tasks` по ключам основных планов (`map:29`) и этапов черновиков (`draft:DRAFT-01.3`). `tools/plan_ai_tools.py` при сборке проверяет каждый `source` на диске (`project:` / `user:` / `plugin:` / `synced:` / `tool:`; `builtin:` — встроен в Claude Code) и добавляет к задаче блок `ai`; рекомендацию он не угадывает: открытая задача без записи получает `state: missing`, выполненная — `retro`. Карточки всех пяти страниц и черновиков показывают сворачиваемый блок «AI Tools & Skills», MASTER — сводку (исполнители, направления, недостающие инструменты, архитектурные проверки, готовое для Codex, блокировки). Статусы и ID этот файл не меняет. Ручная правка допустима: после неё `python tools/build_master_plan.py` и `python tools/check_plans.py`.
